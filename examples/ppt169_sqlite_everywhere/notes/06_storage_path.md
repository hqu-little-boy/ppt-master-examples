Now the bottom half of the rail, layers six to eight. The B-tree layer asks for a page by number, the pager caches pages and provides rollback, atomic commit, and file locking, and the VFS does the actual reads and writes on the operating system's file. Every read and write is a whole page, 4096 bytes by default, and the page size can be any power of two from 512 to 65,536. This strip is one B-tree page in file order: a 100-byte database header that exists only on page one, an 8-byte header for leaf pages or 12 bytes for interior pages, the cell pointer array growing forward, unallocated space, the cell content area growing back from the end, and a reserved region that is usually empty. An interior page holds K keys and K plus one child pointers. Table B-trees use a 64-bit signed rowid key and keep data only in the leaves; index B-trees use arbitrary keys and store no data. There is one B-tree per table and per index, all in the same file, with the schema table rooted at page one. About 4.29 billion pages of 64 kibibytes is where the 281 terabyte limit comes from, and every valid file begins with the string SQLite format 3.
